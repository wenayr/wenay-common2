What is actually on the wire auth.resolveAuth(token) → {object, ack, expiresAt, renewBeforeMs} · [Pkt.AUTH, {state}] · createRpcClientHub(…, {token: provider})

Two gated facades share one socket and one token provider. With gate: true the starting object is the anonymous facade, so a privileged call is refused until a HELLO succeeds. Login is an ordinary HTTP endpoint for the same reason. At expiring both facades alarm and the hub asks the provider exactly once; the renewal is a soft re-auth, so the tick stream keeps its numbering. Expiry and revocation take the same downgrade corridor — the difference is that revocation is a resolveAuth throw carrying revoke: true.

What actually happens Scale.createAuthority (leader) · Scale.createStoreNode (every mini process) · Scale.createClusterClient (this tab + each reader) · createTokenCodec → identity {issue, verify} (crypto stays host-side)

Spawn starts a REAL extra Node.js process serving the same replay line. The directory is an ordinary replicated map; this tab bridges its facts into replica-set offers and moves between processes by seq, so the ticker never loses a value. Drain is data, not a command channel: the mini node watches its own directory row and exits after the grace period.

Writes are the end-to-end trust mode: Login mints a real codec token, every node verifies it LOCALLY (shared secret) in its own gated facade, and each forwarded command carries the token to the leader, which re-verifies it — a mini node never asserts who you are. Revoke is one replicated fact: the leader cuts its sessions, every mini cuts its own on the same data, and writes die on ALL nodes instantly.

Placement is level-2 balancing: each reader picks WHERE TO LAND once by weighted directory facts (the cluster client's own sticky placement) and stays sticky on that node; per-line routes (level 3) still move seamlessly by seq when the facts change. The readers column arrives through the same replicated directory every node and panel reads — observability IS replication.

The scene draws only facts: a box is a live OS process (pid + port from its directory row), a dot is a reader whose route ACTUALLY points there. Kill −9 is failure injection — SIGKILL, no drain, no goodbye — so the red box and the flying dots are a real failover. Autoscale runs at the leader on the same replicated readers facts: 🌊 Reader storm makes it spawn processes under load, Close readers makes it drain them back.
