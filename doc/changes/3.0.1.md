# 3.0.1

Security and correctness release from a four-area code review (RPC, server/service, events/codec,
Observe). Every fix below has a regression test that failed before it; migration rows are in
[NAMING_RENAMES.md](../NAMING_RENAMES.md).

## Security

- Service leader host: a service without `access.login` no longer mints a token for an account the
  client names in the socket handshake, and can no longer lift that account's revocation. The ungated
  identity is `{renew}`; issue tokens server-side (`leader.identity.login(account)` after your own
  authentication, `access.login`, or `createTokenCodec`). Test: `service-leader-identity`.
- RPC: numeric method refs stay pinned to their path across `reauth()`/`control.grant()`; a racing
  user call could previously run a different (admin) method of the new principal. Test: `rpc-route-epoch`.
- RPC legacy protocol (`createRpcServerAutoDetect`): keys resolve as own members with `isSafeKey`;
  a crafted key could install a process-wide setter through the prototype. Test: `rpc-legacy-proto`.
- Replay binary decoder: linear RegExp named-group validation (a 1 MB crafted source blocked the event
  loop for ~3 s); binary views, ArrayBuffers and RegExps cost 16 work units. Test: `replay-binary-decode-cost`.
- Errors carry no server stack frames to peers: HTTP facade/REST bodies never, RPC unless the server
  runs `debug: true`. The operator keeps them: `createHttpFacadeServer({onError})`, service REST `log`.
- `saveKeyValue` refuses `..`, roots, drive/UNC and NUL in `path`/`key`. Shared secrets (webhook bearer,
  service node token, rental example) compare in constant time; the webhook server caps subscribers per
  client IP (`maxSubscribersPerIp`, default 32) and lists only the caller's own address's subscriptions.

## Fixes

- Store: a leaf subscription no longer goes silent when its parent is deleted and recreated in one
  drain window (local writes, `node.replace(null)`, patch batches, replay tail resume).
- Store: node-cache pruning no longer re-checks every cached sibling on each write
  (20k writes with 2k per-key node entries: ~4 s → ~20 ms); it releases the same entries.
- Lazy line: chunks carry detached values; an in-process mirror no longer shares objects with the host.
- RPC: stopping one of two subscriptions to a node that differ only by args/opts leaves the other
  running; core auth timers and flows are released on transport disconnect; an async `onInvalid` on
  the CAPS path can no longer raise an unhandled rejection; PIPE keeps method receivers.
- Replay: a throwing catch-up consumer releases its live subscription (leaked ~160 MB per 1M emits);
  one bad live item no longer drops its micro-batch; `channelFromDataChannel` drops sends once closing.
- Listen: `off(cb)` cancels `once(cb)`; `fast:false` delivers an emit only to listeners present when it
  started (a self-rearming `once` looped forever); `listenSnapshot` connects for the first subscriber.

## Verification

`npm run release:verify`, including the new regression specs listed above and in the commit messages.
