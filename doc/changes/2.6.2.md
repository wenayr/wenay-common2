# 2.6.2

One correctness fix, in the same place 2.6.1 touched.

- **`syncStoreLazyLine` still kept a ghost when the stale arrived PART-WAY THROUGH a first pass.**
  2.6.1 armed the end-of-pass sweep on a stale cursor but reused the accumulator when one already
  existed, so a pass started from a null cursor and interrupted by a stale carried its delivered
  keys into the restarted pass. Those keys are not evidence about the new pass: a key the aborted
  pass delivered and the fresh pass never mentions is exactly the key that must be swept, and it
  survived instead. The set is now REPLACED on every stale, never extended. 2.6.1's test only
  covered a stale on RESUME, where no accumulator existed yet, which is why it passed.
  Reproduced against installed 2.6.1 and covered by a mid-pass host-replacement test.
