# 2.16.0 — the horizontal-scaling tier, typed inputs end to end, consumer bridges

Release theme: the deployment triangle becomes library surface. `Scale.createAuthority` /
`Scale.createClusterClient` / `Observe.createStoreNode` assemble authority, serving node and
balanced consumer from one config object each; the write corridor (`Command.*`) makes commands
at-most-once across nodes; the chunked-keyframe protocol bounds catch-up frames by bytes. Plus the
consumer bridges: the loopback testing kit, `storeExternal`, and the value-semantics contract.

## The horizontal-scaling tier (`Scale`, `Command`, `Observe.createStoreNode`)

- `Scale.createAuthority<T>(deps)` — the single point of order from ONE config object: the replica
  line, the node directory, the command corridor with receipts and end-to-end token verification,
  and the identity lifecycle over a REPLICATED deny list (login lifts the ban, renew refuses
  revoked, revoke cuts live sessions now and every node follows the same fact). `serve.*` are
  audience-ready RPC blocks: `browser(account)`, `reader()`, `nodeLink(linkNodeId?)`,
  `connection()` (RPC-AUTH rules 1/3/6/7).
- `Observe.createStoreNode<T>(deps)` — a serving node from one config object: replica line with the
  to-upstream offer, local token verification + deny-list session cuts, self-registration and
  heartbeat (the `readers` fact = the line's ACTIVE subscriber count), token-envelope command
  forwarding, and leave on the node's OWN directory row (drain is data, no control channel).
- `Scale.createClusterClient<T>(deps)` — followNodeDirectory + sticky weighted placement + the
  offers bridge + a replica set; the pick is not re-rolled on roster churn, and below it the line
  moves gap-free by seq.
- `Observe.createNodeDirectory` / `followNodeDirectory` / `nodeDirectoryViews` / `pickDirectoryNode`
  / `directoryReplicaOffers` — the replicated roster and the ONE pure derivation shared by balancer
  and panels.
- `Command.createCommandHost` / `forwardCommands` / `verifyCommands` / `forwardCommandsByToken` —
  the write corridor: at-most-once per (account, requestId) with receipts, trusted-mirror and
  end-to-end relay modes.
- Chunked keyframe (`doc/target/KEYFRAME-CHUNKING.md`, decided v1): the wire facade's optional
  `chunks` facet splits ONE snapshot into partial keyframes by byte budget; the client reassembles
  and applies through the ordinary single-event path, with monolithic fallback. `replayListen`
  gains `keepBytes` journal accounting; `hub.close()` is the client hub's terminal verb.
- Oracles: `observe/scale-authority.test.ts`, `scale-client(.balance)`, `store-node(.readers)`,
  `node-directory`, `replay/command-host`, `command-token`, `keyframe-chunks`, `journal-bytes`,
  `authority-key-retention`, plus realsocket suites. Living stand: `npm run demo` → Lab → Mini
  horizontal scaling (real extra processes; the tick line survives drain and a hard kill).

## RPC testing kit: `createLoopbackSocketPair`

- New export from `wenay-common2` / `wenay-common2/rpc` (`src/Common/rcp/rpc-inproc.ts`):
  `createLoopbackSocketPair({delivery?: 'micro'|'sync'}) -> {client, server, kill, setOnline, online}`.
  Same detached in-proc wire as `createInProcSocketPair` (JSON round-trip + native binary
  attachments, no identity leaks), plus the two facts a transport test needs to stage:
  `kill()` — definitive socket death, `'disconnect'` on both ends, delivery over;
  `setOnline(false)` — silent-loss window (frames drop, nobody is told), `setOnline(true)` resumes.
- Consolidates the ad-hoc `createLoopback` copies living in 9+ spec files; existing copies stay
  untouched (churn), the export is canonical for new code and for consumers testing their own
  facades without socket.io.
- Docs fix: the rare-docs line advertising this layer named a non-existent `createRpcServerInProc`;
  it now documents the real `createRpcInProc` / `createInProcSocketPair` / `createLoopbackSocketPair`.
- Spec: `src/Common/rcp/rpc-inproc.spec.ts` (end-to-end facade + Listen + binary over the pair,
  offline window, kill semantics, sync delivery, wire detachment) — wired into `npm test` /
  `test:all` as `test:rpc-inproc`.

## Observe: `storeExternal` — the React 18 external-store tuple, zero React dependency

- `Observe.storeExternal(nodeOrStore) -> {subscribe, getSnapshot}` over any `{on, snapshot}` source
  (a `store.node` path or the Store root). `getSnapshot` identity is stable between changes and
  recomputed lazily on the first read after a change fact — the exact `useSyncExternalStore`
  contract, so React consumes a Store path without a re-render loop and the library stays
  framework-free. (`src/Common/Observe/store-external.ts`.)
- `subscribe()` itself invalidates the cache: a change landing in the render→subscribe gap is
  caught by React's post-subscribe re-read (without this the component froze on the stale
  snapshot); one subscriber leaving no longer disturbs the peers' cached identity. Spec:
  `src/Common/Observe/store-external.spec.ts` (`test:store-external` in `npm test` / `test:all`) —
  gap invalidation, identity stability between changes, peer-unsubscribe isolation.

## Observe: reactivity contract pinned

- New spec `src/Common/Observe/store-value-semantics.spec.ts` (`test:store-values` in `npm test` /
  `test:all`) pins the table: plain objects/arrays reactive at any depth (including array in-place
  mutation and coalescing to one fact per drain window); rich values
  (Map/Set/Date/TypedArray/class instances) are VALUES — replacement visible, in-place mutation
  invisible by design, prototypes preserved, snapshots still deep-clone them with full semantics.
- The rule is now stated in `doc/wenay-common2.md` §Observe (it previously lived only in
  `reactive.ts` internals, while the RPC docs advertise Map/Set as first-class — the gap that made
  the wrong expectation easy).

  non-tuple routes keep the generic array + example, and the live leg proves the served 3.1.0

  runtime `input` schema (`template/input-schema.ts` — tiny DSL: scalars, `'?'` optional, enum,
  array, nested object) that is the single source of automatic validation before `validate()`,

  it end-to-end (self-checks 24/24 and 23/23, incl. an openapi-typescript field-level proof).

## The tier's final shape before publication (breaking within this release)

Decided in `doc/target/SCALE-REFACTOR.md`; every rename in `doc/NAMING_RENAMES.md`.

- **One control line.** Roster, deny list and receipts are three SECTIONS of one Store served as one
  Store Replay line (`nodeLink().control`). Nodes and standbys follow it in ONE subscription; a
  promoted standby re-owns every section in the same instant (the followed store CONTINUES as the
  owned line via the follower's own `promote()`). Browsers never see the deny list or the receipts:
  `serve.browser().roster` / `authority.roster.api` is a projection line of the `nodes` section.
  `Observe.createNodeDirectory({store?})` and `Command.createCommandReceipts({store?})` are the
  section facets — standalone they own their store and line, embedded they ride the caller's.
- **Liveness is a fact the roster owner publishes.** `NodeDirectoryEntry.ts` is gone; rows carry
  `alive` and `since`. The owner keeps beats in memory, sweeps every `staleMs/2` and writes a
  verdict only when it changes — a fleet of N nodes costs its followers nothing in steady state,
  and no reader compares a foreign clock against its own (`stale`, reader-side `staleMs`/`now` and
  the anchored `hostNow` machinery are gone). A promoted standby grants the fleet a grace of
  `staleMs`. Stated consequence: if the authority dies the roster freezes alive — clients act on
  last known facts and the replica set's own route health decides per connection.
- **One write rule.** `set(row)` replaces, `patch(nodeId, partial)` merges (meta one level),
  `heartbeat` = liveness + patch, `drain`/`undrain` are named patches, `grace`/`sweep` are the
  owner's liveness verbs; `upsert` is gone. Writes that change nothing publish nothing.
- **Inputs mirror the outputs.** `createAuthority({line, roster, identity, corridor?, leadership?})`,
  `createStoreNode({line, roster, upstream, serve: {onConnection, wrap?, keys?, opt?}, …})`,
  `createClusterClient({line, roster, connect, placement?})`; `StoreLineCoordinates` is declared once
  in `store-replica-set`. `createStoreNode` reports `status().rehomes`.
- Consumers migrated: demo (host, node, browser card), scaffold template + rental example, k8s feeder
  and checks, every tier oracle. Oracles: `observe/node-directory.test.ts` (owner verdicts, embedded
  facet, follower liveness), the rest unchanged in intent.

## Authority succession and durable receipts

- **`Scale.createAuthority({leadership})`** — the same factory now runs as the LEADER or as a STANDBY
  (`role: 'standby'`, `upstream` = the current leader's `nodeLink(standbyId)` resolved by the host,
  `autoPromoteMs`, `elect`/`accept` lease seam pass-through). A standby follows the replica line and
  the control line (roster, deny list, receipts), registers a `'standby'` roster row (weight 0,
  discoverable, never placed) and takes over when the replica set's ONE leadership decision makes it
  leader: lines re-owned from the followed snapshots, the dead leader's row removed, its own row flipped
  to `'leader'`. A leader losing fork choice demotes (writes refuse, names the leader) and follows the
  winner when it has an upstream. A standby never auto-promotes before its first follow;
  `control.promote()` forces. New facets: `control.promote`, `events.role`, `view.role/leaderId/epoch`.
  A standby serves `reader()` only — `browser()`/`nodeLink()`/identity writes throw until it leads.
- **`Command.createCommandReceipts`** + `createCommandHost({receipts: {line}})` / `host.adopt(line)`:
  committed receipts (and their drops) are a replicated line; the successor's host adopts the line it
  seeded from the followed snapshot, so an OLD requestId answers its receipt instead of running again —
  at-most-once now survives the authority process. Boundary stated in the docs: a command in flight at
  the moment the leader dies has no receipt anywhere and may execute again.
- **Store node re-homes**: when `deps.upstream()` resolves a DIFFERENT link (failover or hub rotation)
  the node registers there and follows THAT roster and deny list; the token hop binds per HELLO to the
  current link. Heartbeats tolerate a link whose owner is gone (synchronous throws no longer escape).
- `Observe.createNodeDirectory({initial})` seeds a roster; `tNodeDirectoryRole` gains `'standby'`.
- Oracles: `observe/scale-failover.test.ts` (28 checks; 6 fail without the seeded hand-over),
  `replay/command-receipts.test.ts`. Not in this release: transport rotation at hosts (the demo stand
  stays single-leader; the standby's url is in the roster for a host to use).

## Hardening of the tier (each fix proven by a test that fails without it)

- **Command host** (`command-host.ts`): receipts are bounded ACROSS accounts (`receipts.maxTotal`,
  default 8192) and fully-expired departed accounts are drained, so a public stand stays memory-flat;
  the limiter rides `createRateWindow` (now with injectable `now` and `drop(type)`), so "per rolling
  minute" is genuinely rolling and a drained account keeps its window until the minute is over; an
  in-flight duplicate answers with its OWN copy; fragment construction is ONE internal
  `bindCommandNames` that refuses prototype-shaped command names. Proof: `replay/command-host.test.ts`.
- **Node link identity** (`scale-authority.ts`): every verb refuses the authority's own row;
  `nodeLink(nodeId)` binds a link to one row and refuses foreign ones. The demo and scaffold hosts
  bind every link to the handshake's `node` claim and drop a link that claims none (the fleet token
  stays shared, so the claim itself is trusted — see `doc/RPC-AUTH.md`). `register` accepts the node's
  OWN `{pid?, readers?}` facts and `createStoreNode` sends both, so a crash-restart resets stale load;
  non-finite counts (`1e400` is legal JSON) sanitize to 0; a link-flap re-register keeps the row's
  facts. Proof: `observe/scale-authority.test.ts`, `observe/store-node.test.ts`.
- **Directory** (`node-directory.ts`): `heartbeat` merges `meta` one level (readers vs labels vs pid
  stop erasing each other); `followNodeDirectory` staleness is clock-skew immune — it anchors on the
  freshest host stamp and advances by LOCALLY elapsed time (`opts.now` keeps the direct meaning);
  `directoryReplicaOffers` skips the `replace` when a beat changed no membership and no price; the
  weight→priority mapping is ONE exported `directoryRoutePriority`. Proof: `observe/node-directory.test.ts`.
- **Store node lifecycle** (`store-node.ts`): a failed `start()` throws and stays retryable;
  `leave()`/`close()` racing a slow `start()` wins (a raced registration is goodbyed); `seenSelf` seeds
  from the ready snapshot, so a removal in the very first roster batch still triggers leave;
  `deps.upstream` is re-resolved on every replica reconnect (a hard hub rotation cannot strand the
  node); the node watches its OWN row through `onKey`; rule-7 session bookkeeping is the shared
  `createSessionRegistry` (internal) — the hand-copied version had leaked one entry per departed
  account. Proof: `observe/store-node.test.ts`.
- **Chunked keyframe** (`store-replay.ts`): true LRU retention (`pull()` re-inserts, so a slow client
  mid-assembly is not the one evicted); null-prototype groups and an OWNED merge target keep an own
  `'__proto__'` data key intact and stop the client mutating the producer-retained chunk 0; producer
  opt-out `exposeStoreReplay({chunks: false})` for facades that override `keyframe`; the journal's
  default `keepBytes` measure reuses the admission byte count (and `replayListen`'s rides
  `wire-size.ts`). Proof: `replay/keyframe-chunks.test.ts`.
- **Loopback pair** (`rpc-inproc.ts`): receivers are decided at emit time — a handler registered
  after `emit` or during dispatch never sees the in-flight frame (parity with the real wire). Proof:
  `src/Common/rcp/rpc-inproc.spec.ts`.
- **Demo/experiments**: `MINI_TOKEN` joins the fail-fast env guard; leader/node write clients resolve
  at CALL time through the hub facade; trust tokens and the scaffold HMAC secret mint from
  `crypto.randomBytes` and token gates compare timing-safe; scaffold CORS pins to known origins
  (`SERVICE_CORS_ORIGINS`, `SERVICE_ALLOW_ANY_ORIGIN=1` dev escape); the k8s watch backoff no longer
  resets on ERROR events.

## Docs: two recipes (rare docs, RPC section)

- **Runtime input validation at the RPC boundary**: the `hooks.onRequest` seam with a per-path
  validator table (types erase; `RpcLimits` bounds volume, values are the application's).
- **Store state schema evolution across deploys**: additive change = deploy and nothing else;
  breaking change = bump `lineId` (stale cursors → one fresh keyframe, never a mixed-shape
  mirror); version the shape inside the data for rolling-deploy coexistence; never persist a naked
  seq without its lineId.
