# 2.2.0

- Add in-band RPC authorization lifecycle: `auth.resolveAuth` may now grant a token lifetime
  (`expiresAt`, `renewBeforeMs`), the server pushes `Pkt.AUTH` states (`expiring`/`expired`/`revoked`)
  negotiated by `Caps.AUTH_STATE`, and one downgrade corridor serves HELLO success, expiry and
  revocation. A rejection stays transient unless it carries `revoke: true`.
- Cut the streams a narrowed principal may no longer see: `hooks.onPrincipalChange` reports
  `RpcPrincipalChange {keep, drop}` and `createRpcServerAuto` ends exactly the dropped Listen nodes
  with `RPC_STOP`/`CB_END` before unsubscribing, so consumers resolve instead of hanging. Listen
  nodes inside a `noStrict(...)` subtree are never walked and are deliberately never torn down.
- Correlate a `Pkt.HELLO` with the `Pkt.MAP` that answers it (`Caps.HELLO_ID`, `opt.helloId`): the
  client sends an id in HELLO's 3rd element and the server echoes it in the answering MAP's 6th, so
  an unsolicited MAP (STRICT push, expiry/revocation downgrade) can no longer settle a pending
  `reauth()` with a stale ack. Uncorrelated peers keep the previous wire byte-for-byte.
- Return a `control` facet from `createRpcServer` / `createRpcServerAuto` (previously void / `{api}`):
  `control.revoke(reason?)` runs the same downgrade corridor an expiring token takes, and
  `control.grant(grant)` applies a principal without a client HELLO, so an admin action, a logout
  elsewhere or a fraud signal no longer has to bounce through the client. Both return `false` only
  for a detached connection; an application grant is deliberately uncorrelated. Exported derived type
  `RpcServerControl` for a per-session `Map<userId, RpcServerControl>` registry.
- Report a granted token's deadline to the renewing side without touching the application's ack:
  the server attaches `ack.$rpc = {expiresAt}` on a copy under the reserved `GRANT_FACTS_KEY` and
  passes the ack through unchanged when it is not a plain object, already owns the key, or has no
  finite deadline. The client reads it defensively and reports the new local auth state `'renewed'`
  with the deadline it found.
- Add the client renewal seam: `onAuthState` (server states plus the local `'renewed'` and
  `'renewFailed'`), `setTokenRenew`, single-flight renewal with a same-token guard, and exactly one
  retry per unauthorized waiting call — never for fire-and-forget, callback-carrying calls, PIPE or
  Listen. A manual `reauth()` and an application `control.grant` deliberately emit no `'renewed'`.
- Add the hub token provider `hubOpts.token` plus `authListen`: one function owns the whole token
  lifecycle, starts the hub, and is single-flighted across facade clients. An explicit
  `connect`/`setToken` token now wins for the ONE connection wave it raises instead of every wave
  after it, so a reconnect asks the provider again rather than re-presenting a refused token;
  `reauth(token)` claims no wave at all.
- Answer `auth()` for a client that presented no token with a local
  `{ok: false, reason: 'RPC client presented no token'}` instead of leaving the waiter undrained, and
  run the handshake guard before the renewal in `init()` so the documented `init()` + `ready()`
  sequence mints one token and sends one HELLO per connection.
- Add `createTokenCodec` to `wenay-common2/server` as the runnable default behind `resolveAuth`
  (one secret, pinned HMAC-SHA256 under a `v1` tag, minted `exp`/`jti`, 15-minute default TTL);
  no JWT, key rotation, revocation list, refresh flow or identity provider, on purpose.
- Batch the two directions that never batched: `opt.requestBatch` (`Caps.REQ_BATCH`) carries a
  session's `CALL`/`PIPE` and its `RESP`/`CB_END`/`CB` in one new ordered envelope, `Pkt.BATCH`, so a
  burst of concurrent calls costs one frame each way instead of one per call. Because a response then
  shares the queue with the callbacks it must follow, the RESP ordering barrier is not skipped but
  unnecessary — order is carried by position in the batch. `createCallbackPacketBatcher` was
  generalized (envelope opcode as a dep) rather than duplicated, and it now inspects a packet only
  once a second one shares its frame: a lone packet leaves unwrapped either way, so the isolated
  request path pays no extra `JSON.stringify`. A distinct opcode, not a widened `Pkt.CB_BATCH`, because
  the shipped client validates that envelope against `CB`/`SHAPE`/`CBV` and would drop a response.
  OFF by default, unlike every other bit: measured on `experiments/rpc-perf-2026-07`, the `burst`
  family goes 100 frames → 2 with 2.27× throughput, −72 % CPU and −12.1 % / −6.0 % bytes, while the
  isolated `small` family gains nothing and must not pay a microtask for it.
- Put every Replay surface behind the same real slow-client gate. Store Replay V2 facades
  (`exposeStoreReplay().api.replay`, including `createReplicatedMap().api`) and prepared
  `exposeReplay(...)` facades now carry private sequence metadata, so `createRpcServerAuto` projects
  `frameLine` without shape-sniffing. A raw or prepared gate attaches to its source only on the
  first actual `frameLine` consumer, detaches on the last `off()`, and starts the 25 ms default poll
  only after that consumer crosses `highWater`; connected clients which never subscribe cost no
  Replay fan-out or poll timer. Real-Socket.IO coverage holds a V2 follower above highWater through
  50 writes (zero live deliveries), then verifies one compact recovery frame after drain.
- Compare the legacy RPC stream-stop sentinel by exact string identity. A Store Replay V2 envelope
  can contain safe objects without a prototype; coercing that application array merely to ask
  whether it was `RPC_STOP` could throw before delivery.
- Stop paying for repeated key names: `opt.compactRows` (`Caps.ROWS`) sends an array of uniform
  plain-object records as its keys once plus rows of values — `{"$_t": [shapeId, rows, keys]}` — in
  results and callback arguments alike, and `sendResult` compacts at all for the first time. One
  bounded connection-scoped shape registry replaces the per-`cbId` table the benchmark found leaking:
  at most 64 shapes, evicted least-recently-used, monotonic ids that are never reused, declaration
  tracked per session, and the client's table bounded at 256 and cleared on each server generation.
  A table always carries its own keys and never writes the `Pkt.SHAPE` table, so it cannot
  desynchronize when the receiver drops a packet it cannot use, and no shape id can make a table
  decode against another producer's key order; what the shared registry buys is the shared id space
  and the shared uniformity judgement — a shape an array proved uniform lets the tick path skip the
  five-repeat threshold. Encoded from 4 records up, only for plain objects with identical key order
  (preserved end to end), and never when a value would change meaning by moving into an array
  (`undefined`, functions, symbols are dropped from an object by `JSON.stringify` but become `null`
  in a row). Decoding re-validates keys, counts rows against `maxArrayLen`, keeps values at the depth
  they would have had as `{…}[]`, and rejects a row whose width disagrees with its shape rather than
  padding it. ON by default, unlike `requestBatch`: on `experiments/rpc-perf-2026-07` the `large`
  family goes 127 912 → 70 983 B/call (−44.5 %) with p50 −24 %, throughput +26 % and CPU per call
  unchanged, while `small`, `ticks`, `flood` and `burst` stay byte-identical.
- State and narrow the RPC codec's reserved-key contract instead of escaping it. `$_d` `$_m` `$_s`
  `$_r` `$_b` `$_f` `$_t` are the codec's keys in one position — the single key of a plain object —
  and that is now documented in one place (`doc/wenay-common2-rare.md`, "RPC application wire", with
  pointers from the brief doc and `rpc.md`) instead of being discoverable only by reading
  `rpc-walk.ts`. Escaping was rejected on its old-peer story, not on cost: it changes the bytes, so
  it needs its own capability bit, and against a peer without the bit it swaps one silent corruption
  for a differently shaped one. What shipped instead: **recognition as narrow as the payload each
  serializer emits**, so only what this encoder can actually produce is taken back — `{"$_b":"x"}`
  and `{"$_m":5}` no longer throw a SyntaxError/TypeError out of the decoder and reject a whole
  response, `{"$_r":5}` no longer becomes `/(?:)/`, and a `$_t` payload that is not shaped like a
  table is an ordinary object rather than a `PayloadLimitError`. No bit is needed because no version
  of the encoder ever emitted a payload that fails the new tests, and the bytes going out are
  byte-identical for library values and colliding application values alike. One behaviour is
  deliberately changed towards the truth: `JSON.stringify` writes `null` for an Invalid Date's NaN,
  and `{"$_d":null}` is now restored as an Invalid Date instead of the epoch. Plus **encode-side
  detection**, the only side where the question is decidable: with `debug` on the server factory or
  `api.log(true)` on the client, every outgoing collision reports itself as
  `[RPC OUT] reserved key $_x …`; with debug off the check is one register test on a branch that
  only colliding values enter, and `large`/`ticks`/`small` are unchanged on
  `experiments/rpc-perf-2026-07`. Exported `RESERVED_MARKER_KEYS` and `reservedMarkerKeyOf(value)`
  so an application can assert the contract on its own data. New spec
  `src/Common/rcp/rpc-marker-contract.spec.ts`, wired into the gate as `npm run test:rpc-markers`.
- Type-check the executable specs the gate already ran blind: new project `tsconfig.spec.json`
  (`npm run test:spec-types`, wired into `npm run test` and `npm run test:all` right after
  `test:types`) compiles `src/**/*.spec.ts` — `rpc.harness.spec.ts`, `rpc-callback-batch.spec.ts`,
  `https-config.spec.ts` — under the library's own options with nothing relaxed, only `noEmit` added,
  so `npm run build` still emits no spec into `lib/` or `dist/` and the published `files` list is
  unchanged. The include is a glob: a new spec under `src/` is checked without touching the config.
  Cleared the 21 errors that had accumulated while the file drifted unchecked — 19 `TS4111`
  (index-signature members now reached with brackets), one `TS7006` (rejection handler annotated),
  and one `TS2339` where `let c: RpcClientReturn<any>` had erased the client's real form and made
  `c.strict.node.ping()` unresolvable. All type-only: the harness still reports 337 assertions and
  `ALL GREEN`.
- Document the authorization surface: new canonical page `doc/RPC-AUTH.md` (rules with correct and
  wrong code pairs, exact signatures, documented limits), an `rpc.md` §5 mirror, and brief/rare
  public-surface entries. `rpc.md` §3.1 no longer shows the token in the socket handshake query.
