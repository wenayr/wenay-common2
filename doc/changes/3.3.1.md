# 3.3.1

## Security

- RPC below a `noStrict` node resolved a name with `in`, so every method a value inherits from a
  builtin prototype was a call target: a peer could plant an accessor on host data
  (`__defineGetter__`), call `hasOwnProperty`/`toString`, and mutate host data through an array's
  `push`/`splice`, a Map's `clear` or a Date's `setTime`. Such a name now resolves only when the node
  owns it; the call answers "Not a function". Members answered by a proxy's `has` trap and a host
  class's own prototype methods stay reachable.
- One rule for RPC and MCP: the resolver moved from the MCP walk to `src/Common/rcp/rpc-member.ts`
  (internal); MCP `noStrict` templates and the dispatcher use the same function.
- Oracle `oracle/regression/rpc-nostrict-builtins.spec.ts`: each attack through an ordinary client
  string path, the host data unchanged, and the application's own surface (own methods, a class
  method, an own `clear`, a `has`-trap member) as controls; 11 checks fail on 3.3.0.
- Docs: RPC-AUTH Rule 3, rare doc *noStrict*, `rpc.md`.
