# 2.3.0

- Add `createStoreReplayView`: a read-only top-level key view over one authoritative Store. Views
  share one selected exact-path Store watcher, detach each changed value once for all interested
  views, keep only a key set and filtered V2 journal, and do no clone, sequence or fan-out work for
  unselected changes.
- Add bounded key-by-key bootstrap through callback chunks and cumulative RPC read windows. The
  client assembles off-Store, commits one atomic root, then applies the retained V2 tail; cursor
  expiry/history eviction retries without exposing partial state.
- Add `syncStoreReplayView` with `{lineId, selectionId, seq}` cursors, identity-safe tail resume,
  line/authorization reset, cancellation-safe external snapshot hooks and session/window limits.
  One top-level value remains indivisible in V1.
- Cover 1,500-to-500 selection, live projection, fuzzy scan races, cancellation, eviction retry and
  special keys. A real Socket.IO run transfers a 10.50 MiB selected snapshot as 113 callback chunks
  over 56 bounded response windows before one visible Store commit.
- Count ordinary JSON/binary Store patch wire sizes without materializing a second packed graph,
  JSON string and UTF-8 buffer. In five isolated 50 MiB runs this halves windowed snapshot CPU
  (110 to 55 ms) and temporary heap (42.50 to 20.80 MiB) without changing wire or bounds.
