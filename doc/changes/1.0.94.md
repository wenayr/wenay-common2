# 1.0.94

- Rewrite Store Replay v7 as the unchanged v2 `[2, seq, ts, patches]` value. Remove the additional
  top-set/top-delete/root-set opcodes, Store-owned schema catalog and nested msgpack payload.
- Add negotiated universal RPB/3: `msgpackr` encodes the complete existing RPC packet once, covering
  CALL, RESP, PIPE, callbacks, callback batches, errors and Store v7. `{binary:{msgpack:false}}`
  retains RPB/2, `{schema:false}` retains RPB/1, and old peers retain legacy arrays.
- Make Store Replay v2 over JSON arrays the measured default. Later Store members remain readable
  when v2 is absent, while all binary RPC versions now require explicit `binary:true`/binary options.
- Document v7 as the deliberate high-frequency alternative for a dedicated binary RPC connection
  whose batching window consistently produces roughly 50+ changes per physical frame. JSON versus
  binary remains connection-wide, not a per-batch switch. Keep v2 for shared/general connections
  and ordinary one-to-ten updates; retain v3-v6 only for compatibility and diagnostics.
- Do not redesign or recommend Store Replay v3-v6: their measured speed improvement was not
  satisfactory relative to maintaining four additional codecs. Schedule their removal for the next
  intentional breaking release, after a deprecation release and a supported-consumer capability
  audit; this release keeps their wire members readable and therefore remains non-breaking.
- Keep callback functions out of business values with a private msgpack extension while preserving
  the existing RPC callback lifecycle and error/data-only result projection.
- Verify exact V7/V2 logical equality, representative primitive/rich/binary round trips, repeated
  5/8/16/30-field values, real Socket.IO delivery, a 15,000-key keyframe, 250 live updates and
  reconnect recovery.
- Refresh the focused legacy JSON / v2 JSON / v7 binary benchmark with separate Node/Bun
  encode/decode columns. V2 wins total CPU for 1/10 updates and the 15,000-key keyframe on both
  runtimes. V7 remains smaller on the wire and wins total CPU for the measured 50/250 update
  batches, but is no longer recommended as the automatic route.
