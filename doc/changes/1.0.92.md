Old client + new server remains on `replay.line`; new client + old server falls back to it. Batches are bounded by items and the physical v1-v5 rich/binary-aware packed sizes plus the selected outer representation of v6; bounds may split one source drain and optional delay may merge adjacent drains.
- Extend batching through raw Store `patchesBatch`, follower/offline/manager, replica/route plumbing, and opt-in playback. Offline snapshots persist replay mode with seq; independent replica routes stay on canonical legacy coordinates unless explicitly declared to share one batch line. Snapshot subscriptions are installed before the initial read, closing the initial-sync race.
- Make durable replay precommit before head/fan-out, add atomic optional `ReplayStorage.putEvents`, retained `retry()`/`flushPending()` after storage failure, observer-error isolation, and non-transactional safe-prefix accounting. The FS adapter writes a natural batch as one `b` JSONL record, keeps old `e` records readable, and truncates a torn final record on open.
- Add negotiated lossless RPC callback packet batching (`CB_BATCH`, 64 items / 64 KiB), with response/error/end barriers, binary aggregation, reconnect renegotiation, and compact SHAPE collision/prototype hardening. Batch Peer publish/repair, direct replay-channel traffic and packet-mesh route updates with mixed-version fallback and re-entrant delivery protection.
- Add negotiated universal binary RPC application frames for CALL/RESP/PIPE/callbacks and errors. A generation-correlated, whole-bundle-version byte probe protects old peers; `ready()` waits for the correlated mode, byte-blocking adapters fall back after 250 ms, and a late ACK upgrades recoverable Listen subscriptions. `binary:false` preserves the legacy path. Exact value tags cover heterogeneous primitives, rich values, sparse arrays and standard binary views, while per-direction/per-generation ordered-layout caches are transactional, bounded to 1,000 emitted entries and fall back to self-describing objects after saturation. Receivers accept the protocol-wide 1,000-entry maximum regardless of local encoder tuning. Binary callback batches remain one physical attachment with call-time snapshots; 1,024 callback refs and all value/depth/byte work are hard-bounded, including pre-serialization checks for server results, callback snapshots and error data. Runtime-new RegExp/Float16/dynamic-buffer forms and non-canonical native own state fail closed for Node 16 interoperability, values outside the binary envelope reject explicitly instead of taking a lossy marker/JSON fallback, sessions isolate multiple clients on one socket/key, and malformed frames in either direction reset the affected binary session before cached shape references resume. Unequal cache settings, reconnect, server replacement and synchronous re-entrancy have dedicated oracles.
