# 1.0.93

- Add the recommended Store Replay v7 route: flat top-level set/delete and root-keyframe key/value arrays are encoded by `msgpackr` inside the existing RPB/2 callback envelope. Mixed/nested patches keep the compatible v2 tuple fallback inside the payload; application code continues to receive ordinary keys, values and `StorePatch` objects.
- Keep dynamic Store keys out of the shape catalog. A server-owned, append-only catalog shares up to 1,000 recurring nested value-object layouts; clients report known schema ids as canonical singles/ranges such as `[1,3,[5,15],18]`, so live, catch-up, frame, keyframe and reconnect send only missing definitions.
- Preserve rollout compatibility: old clients continue on the unchanged legacy line, new clients fall through v6-v1 when v7 is absent, and a new server exposes every prior member. V6 remains available only as a compatibility generation; v7 is the recommended new/new route.
- Optimize large snapshots and small binary packets. A 15,000-key root is flattened without caching the root dictionary as a schema, ordinary decoded keys use direct own-property writes with an isolated safe `__proto__` path, and msgpackr payloads are marked as codec-owned trusted binary leaves so RPB/2 does not enumerate every byte index.
- Verify strict decoded equality for ordinary Store data, large/special numbers, valid Unicode, arbitrary-size BigInt, valid/invalid Date, RegExp source/flags, Map, Set, ArrayBuffer, DataView and standard TypedArrays over direct and real Socket.IO paths. Document msgpackr representation boundaries: scalar `-0`, sparse holes, lone UTF-16 surrogates and nested null-prototype identity are normalized; normal thrown RPC errors remain on the separate exact RPC error channel.
- Add `npm run bench:store-replay:v7`, a bounded release benchmark covering only legacy JSON, v2 JSON and v7 binary at 1/10/50/250 changed records plus a 15,000-key keyframe. On the recorded Node v24.18 run, 250 changes were 32,657/16,034/7,031 warm bytes and 367.68/144.80/95.81 us total codec CPU; the keyframe was 513,960/513,914/330,032 bytes and 9.59/9.71/7.38 ms.
- Improve RPB/2 trusted encode hints with staged exact-schema runs, stable source-address hints and one-pass layout/write reuse while retaining mismatch fallback, transactional cache updates and exact decoding tests.
