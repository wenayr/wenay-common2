# 3.3.0

## Security

- The HTTP facade (`createHttpFacadeServer`, and so `createHttpFacadeOpenApi`) no longer routes Listen or
  replay streams, a branded `on`, or `noStrict` subtrees. Before, every member of a Listen api object was a
  route (`emit`, `close`, `run`, `on`, `off`, `onClose`…; about 30 for a `replayListen` line): a caller past
  the middleware could forge events into a journal, close or restart a producer, evict subscribers, or
  plant a non-function subscriber that made the next `emit` throw, and the GET mirror made these
  state-changing GETs. `noStrict` keys present at setup were frozen into routes and published in the
  OpenAPI document. These requests now answer 404, and the routes drop out of `routes()` and OpenAPI.
  A plain function stays a route whatever its signature; a replay wire facade keeps
  `since`/`keyframe`/`frame`.
- A stream or `noStrict` root object is refused at setup, by HTTP, OpenAPI and MCP
  (`createMcpFacadeServer`, `control.derive`; `control.mount`/`replace` refuse a stream), instead of
  exposing `emit`/`close`. MCP serves a mounted `noStrict` object as a resource template (below).
- Migration: wrap what must stay callable in an explicit function (`publish: v => emit(v)`,
  `count: () => stream.count()`).
- One classifier in the shared walk (`facadeWalk.ts`, internal), in RPC's order: `noStrict` first (a
  dynamic Proxy is never enumerated), then a Listen api (replay brand or the eight Listen-core functions),
  then a branded `on`. MCP tool and resource lists are unchanged. Only registered or branded streams are
  recognized: a `toSlimListen` object or a bare `emit` in the facade stays a route.
- Oracle `oracle/regression/http-facade-streams.spec.ts` (real Express: 404s, stream state intact after
  the forged calls, an explicit `publish` route as the negative control, OpenAPI paths = routes, root
  refusal, classifier cases); `mcp-facade-server.spec.ts` checks OpenAPI routes = MCP tools over a facade
  with streams and `noStrict`.
- Docs: rare doc *HTTP facade server* and the MCP walk, the brief MCP line, DYNAMIC-RUNTIME adapter limits.

## MCP

- `noStrict` nodes are MCP resource templates: `facade://P/{key}` in `resources/templates/list` (and
  in-process `resources.templates()`), never in `resources/list`. `facade://P/<key>[/<member>...]` reads
  a store's current value, data as JSON or refuses a function by name; any Listen below a key can be
  subscribed. Keys resolve per request as RPC resolves under `noStrict` (`in`, so a proxy's `has` trap
  is the access point; only an object holds members), except that methods inherited from a builtin
  prototype (`Object`, `Function`, an array's `push`, a Map's `clear`, a Date's `setTime`…) never
  resolve unless own or overridden by a host class; forbidden segments, `maxPathLen`, one canonical URI
  per key (percent-decoded). A subtree holding a `noStrict` node is not read whole.
- **Exposure change:** templates are on by default whenever resources are, so after an upgrade
  Listens and plain data under a `noStrict` node become readable by the same principal. Opt out per
  node with `policy.dynamic: path => false`; `resources: false` turns all resources off.
- `policy.dynamic(path) == 'call'` adds one stable dispatcher tool `P.call` `{key, method: string[],
  args?}`: the member runs with its parent as `this` through the same queue, `around` chain and audit
  (`ctx.tool` = `P.call`, `ctx.path` the concrete path). Listen `emit`/`close`, inherited builtins and
  data are never call targets. Read-only servers check the dispatcher and each member; `strict` refuses
  an undescribed `'call'` node at setup and an undescribed member at call time; undescribed members are
  reported once per `P.*.member`, at most 64 per node.
- New, MCP entry only: `describeDynamic(node, {description, title?, key?, members?, annotations?})`,
  `dynamicMeta`, `FacadeDynamicMeta`, `tMcpDynamic`, `policy.dynamic`. A `key` schema is checked before
  any trap of the node runs. `members` is keyed by the dotted member path, so a member whose own name
  holds a dot never takes another member's entry (or its `readOnlyHint`).
- `resources.completions: true` (default off: the method is server-wide) answers
  `completion/complete` for template keys with the keys the `has` trap allows.
- `attach` also claims `resources/templates/list` whenever it claims resources; a conflict names the
  option that caused the claim.
- Fix: a resource read is bounded by `RpcLimits` before packing — a cyclic store value was a stack
  overflow (`RangeError`), now a `PayloadLimitError` — and bytes are refused (`E_MCP_BINARY`) instead of
  being stringified as `{"0":1,…}`.
- Fix: a subscription records its source; a recomposition keeps it only while the new composition
  serves the same stream or dynamic node (a templated subscription used to survive an unmount).
- Fix: a static resource subscribed through an equivalent spelling (`facade://events/./price`) is
  unsubscribed through the same spelling; it used to stay subscribed until the session closed.
- Fix: a resource URI is matched once per request, not once per static resource, and a URI with more
  segments than `limits.maxPathLen` is unknown before any template lookup (a long URI used to cost time
  quadratic in its segments: a 16 000-segment URI took seconds).
- RPC scope hooks (`hooks.onRequest`, `bindRpcScopes`) do not run over MCP: admission for a key belongs
  in `around` or the node's `has` trap (RPC-AUTH *noStrict over MCP*).
- Oracle `mcp-facade-server.spec.ts`: `dynamicTemplates`, `dynamicDispatch` and `dynamicHardening`
  sections, templated subscriptions released by unmount, per-principal templates over HTTP; the F4/F5
  checks and each hardening check fail without their fixes.
- Docs: rare doc *Dynamic nodes*, the brief MCP block, RPC-AUTH *noStrict over MCP* (mirrored in
  `rpc.md`), DYNAMIC-RUNTIME *MCP is optional*.
