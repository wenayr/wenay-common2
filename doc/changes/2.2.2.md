# 2.2.2

- Stop sizing an indivisible oversized Store Replay V2 patch twice. The batcher now reuses the
  successful per-patch metric, adds the exact fixed V2 envelope cost, and preserves the existing
  batch boundary and exact `batchStats().estimatedBytes`. The same admission path keeps a successful
  non-binary metric when a preceding batch flushes; raw Store `patchesBatch` does likewise. Native
  binary patches still restart their attachment indices. On the 4.5 MiB regression payload this
  removed about 51% of the local sizing-corridor time.
- Keep a replicated-map publication baseline only for an injected Store. An owned map no longer
  creates and retains an unused complete `store.snapshot()` at construction. Injected maps update
  their detached baseline from the already-normalized top-level patches after a successful journal
  emit instead of deep-cloning the complete Store after every drain; the final close comparison and
  pending-state handoff remain unchanged.
- Add traversal-count, exact-byte, native-binary, batch-boundary and injected-close regression
  coverage. The binary-placeholder sizing graph is deliberately unchanged in this release.
