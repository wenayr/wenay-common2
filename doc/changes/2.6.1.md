# 2.6.1

Three correctness fixes, one of which affects replay lines that do not use any new API.

- **Replay journal held far more than its configured window (regression from 2.5.0).** Replacing
  the fixed-modulo ring with a head/tail window left the consumed prefix physically referenced
  until the next compaction, and compaction only ran at 1024 evicted slots. At `history: 256` the
  API reported 256 entries while the array still pointed at up to 1281 event graphs — about 5x the
  configured window, and the smaller the window the worse the ratio. An evicted slot is now
  released at eviction rather than at compaction, so the journal holds exactly its window as the
  ring it replaced did; compaction dropped to a 64-slot threshold and now reclaims empty slots
  only. Covered by a retention test and a 50 000-event bounded-array test.
- **`syncStoreLazyLine` left deleted keys alive after a stale cursor.** The stale branch reset the
  cursor but not the mirror, so a key whose tombstone had expired while the subscriber was away
  stayed in the mirror forever while the host no longer had it. A pass from a null cursor now
  records every key it delivers and sweeps anything the pass never mentioned, at the END of the
  pass so the mirror stays populated throughout instead of flashing empty. The sweep runs before
  `filled` settles, so awaiting it guarantees a mirror holding exactly what the host holds, and the
  swept count is reported through `onProgress`.
- **A lazy cursor from a previous host lifetime was silently trusted.** A revision counter only
  means something inside one lifetime: after a restart it begins again, the host found nothing to
  catch up, and the fill resumed past keys the subscriber only assumed it held — permanent silent
  divergence. `StoreLazyCursor` now carries `lineId`, a foreign one is refused as `stale`, and
  `exposeStoreLazyLine` accepts an explicit `lineId` for a host that genuinely preserves its
  revision counter across restarts. `replay-listen` already guarded the same hazard by refusing a
  seq "from another server lifetime"; the lazy line had not inherited it.
- `syncStoreLazyLine` no longer unrefs its timer while the first pass is incomplete: a caller
  awaiting `filled` in an otherwise idle process could see the fill stall silently. Live polling
  after the first pass still does not hold the process open.
- Audited every other "start over" path for the same defect class and found them sound:
  `syncStoreReplay` applies a keyframe as a root replacement, `syncStoreReplayView` commits with
  `store.replace(root)`, `store-offline` and `store-playback` build a fresh Store, and
  `replicated-map.replaceAll` computes removed keys explicitly in both branches.
