# Runnable examples — by level

Each example is a whole copyable project over the installed package (`npm install`,
`npm run typecheck`, `npm start`, `npm run check`). Copy a whole directory; its local host
files (the scaffold template copies: `leader.ts`, `node.ts`, `access.ts`, `rest.ts`,
`panel.ts`, `config.ts`, `input-schema.ts`) are part of the example, not extra library exports.
The three service examples are one authored domain module plus the unchanged template — the same file set,
the same process entrypoints, the same growth path (one process → serving nodes → standby).

| Level | Example | What it adds | Proof |
| --- | --- | --- | --- |
| 1 | [rental](rental/README.md) | one service: typed client, replicated state, commands with receipts, HTTP + Swagger, serving nodes, node restart | `npm run check` |
| 2 | [pizzeria](pizzeria/README.md) | identity above the library (login/signup, password hashes in state), five roles, per-role facades pruned AND enforced, per-audience view lines (secrets never ride a line that hides them), the generic role panel | `npm run check` |
| 3 | [apartments](apartments/README.md) | external effects: a payment intent → provider port (fake bank or a Stripe-shaped adapter) → signed webhook with an effects runner and a ledger of every provider event, a lock device on the client facade with its own account and command line, access codes for guests, a durable authority (state AND receipts) that survives a restart | `npm run check` |

Focused probe: [smart-home](smart-home/README.md) grows from local telemetry to independent
household Stores, idle line reclamation and two owner processes with gated RPC and file archives.
It checks exact value types, several readers, owner crash/restart and a stable client Store.
Its explicit household placement needs no service template or automatic ownership election.

Product probe: [hosting](hosting/README.md) runs a local automated host with stable tenant URLs,
real application processes, prepared updates, request draining and rollback through Contract.
`npm start` leaves the host running; `npm run example` walks through updates and finishes.

Product probe: [small-jobs](small-jobs/README.md) models a small work marketplace: customer posts,
workers propose, customer assigns and accepts a submitted result. Existing command/access/client
resources enforce competing transitions and private views; no payment provider is needed to start.

Product probe: [ai-support](ai-support/README.md) starts a support drafting page with task progress,
cancellation and account separation. Its explicitly labelled template provider needs no model key;
the RPC check reconnects the original Store to a living AI host.

Product probe: [document-processing](document-processing/README.md) uploads plain UTF-8 text,
processes it through FileJob and downloads a JSON report. The processor is deterministic, needs
no model key, and exposes storage, task cancellation and per-account ownership as separate boundaries.

No database in this configuration: the archive on `SERVICE_DATA_DIR` holds the state and the
receipts, `version` + `migrate` in the definition evolve the schema, and the same storage port
takes a DB adapter when a product ever needs one.

Read the level you need; each README states its boundaries (what it does NOT claim). The
in-repository sources live under `experiments/wenay-scaffold/examples/<name>`; the copies here
are regenerated by `npm run examples:generate` and verified from the packed tarball by
`npm run test:examples`.
