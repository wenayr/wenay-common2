# Умный дом: от показаний до независимых процессов

Небольшой SaaS-прототип на публичном `wenay-common2`: устройства отправляют показания,
телефон и планшет следят за состоянием своего дома. Скопируйте весь каталог:

```sh
npm install
npm run typecheck
npm start
```

`npm start` запускает короткий `example.ts`: телефон читает дом Анны, счётчик отправляет
показание, подписка телефона получает его. Стенд поднимает два процесса на свободных
localhost-портах и завершает их после сценария. `npm run check` проверяет все этапы.
Это исполняемые сценарии без графического интерфейса и реального оборудования.

Обычный путь использования: создать читателя и устройство, дождаться их `ready`, подписаться
через `phone.store.node.devices.meter.reading.on(...)`, отправить
`await meter.control.record(21.5)`, при завершении отписаться и вызвать `close()`.
Успех команды означает подтверждение записи; получение обновления телефоном — отдельное событие.

## Этапы

| Этап | Проверка | Что доказано |
| --- | --- | --- |
| Точные значения | `npm run check:local` | `0`, `false`, `"0"`, `null` сохраняют тип у нескольких читателей; секреты не попадают в домашнюю линию |
| Независимые Store и срок жизни | `npm run check:lifecycle` | изменяется только проекция нужного дома; последний читатель уходит — проекция освобождается; сохранённый фасад получает свежий снимок при возвращении |
| Ресурс процессов | `npx tsx stand-check.ts` | одновременные перезапуски объединяются; закрытие стенда побеждает перезапуск; процессы завершаются |
| Реальные сокеты и восстановление | `npm run check:process` | два дома в разных процессах, ограниченные RPC-фасады, аварийное завершение, сохранённые показания и переподключение тех же клиентов |

## Границы кода

| Файл | Ответственность |
| --- | --- |
| `example.ts` | короткий путь чтения, подписки и записи с явным закрытием ресурсов |
| `service.ts` | `control.record` для доверенного входа, `source.household` для домашней линии, `view.stats`, `close` |
| `host.ts` | Socket.IO, проверка HELLO-токена, фасад читателя или устройства, отдельный файловый архив дома |
| `client.ts` | стабильный Store читателя, состояние соединения в `health`, команды устройства |
| `stand.ts` | явное размещение домов по процессам, временные данные, выдача тестовых токенов и управление процессами |

Один дом — один Store. Устройства индексируются по владельцу, поэтому изменение дома Анны
не пересчитывает дом Боба. Публичная проекция создаётся при подписке или чтении снимка,
а после отсутствия читателей в течение `idleMs` (по умолчанию 1000 мс) освобождается.
Новые факты устройств продолжают сохраняться, пока публичной проекции нет.

Стабильный фасад сохраняется до `service.close`. При пересоздании проекции её последовательность
продолжается выше предыдущей; старый курсор требует свежего снимка. Авторитетный Store и архив
живут до закрытия сервиса. `view.stats` показывает число домов, активных проекций, читателей и
пересчётов. Само чтение этих счётчиков не открывает проекцию.

## Сбой и восстановление

В стенде явно задано: Анна → первый процесс, Боб → второй. Это разделение владельцев записи,
а не две копии одного общего состояния. После аварийного завершения первого процесса второй
продолжает принимать показания. Перезапуск использует тот же порт и архив.

`storage(home)` — существующий порт `ReplayStorage`. `record` вызывает `archive.flush()` перед
успешным возвратом. Проверка аварийно завершает процесс после подтверждения и получает прежнее
значение после перезапуска. Это подтверждение записи адаптером, не транзакция с физическим
устройством и не гарантия сохранности при потере питания диска.

Проекция после перезапуска процесса имеет новую последовательность. Клиент использует
`syncStoreReplay` с `prepareCatchUp: () => ({reset: true})`: на переподключении принимает
свежий снимок в **тот же локальный Store**. Последнее значение остаётся доступно при отключении,
но `health.state.state` сообщает `offline`; команда отключённого устройства явно отклоняется.
Читатель и устройство восстанавливают свои соединения независимо.

## Доступ и ограничения

- Токен передаётся в HELLO, исходный RPC-фасад пустой, включён `gate`. Подписанные claims
  определяют дом и роль. Читатель получает только свою линию; устройство — только `record`,
  привязанный на сервере к его id. Нет удалённого метода выбора чужого дома.
- Читатель не может отправить поддельные события, выполнить запись или закрыть общий источник
  других читателей. Полный Listen передаётся RPC-адаптеру как распознаваемая структура;
  самодельный объект `{on: original.on}` меняет адресацию и не заменяет этот ресурс.
- Выдача токенов в `stand.ts` — доверенная тестовая композиция. Продукту нужны собственные
  логин, политика доступа и размещение. Все процессы на одной машине; это не кластерный тест.
- Размещение статическое. Нет автоматического переноса владельца, выборов, репликации между
  владельцами или общего балансировщика. Передача записи другому процессу требует отдельного
  решения о владении и fencing, а не одного таймера.
- Обёртка ленивой replay-линии не переносит внутреннюю маркировку автоматического RPC
  backpressure. Здесь небольшие показания, `throttle` не включён; режим больших потоков и
  медленных читателей потребует отдельной проверки. Публичный перенос этой маркировки —
  отмеченный кандидат на обсуждение API, а не обещанная возможность примера.
- Файловый адаптер — локальный журнал. Ошибка записи не означает откат уже изменённого Store.
  Повтор присваивания показания идемпотентен по значению; пример не моделирует денежные эффекты.
- Стенд удаляет свой временный архив при закрытии. Для самостоятельного `host.ts` задаются
  `SMART_HOME_INITIAL`, `SMART_HOME_SECRET`, `SMART_HOME_DATA_DIR`, необязательные
  `SMART_HOME_PORT` и `SMART_HOME_IDLE_MS`; при IPC-запуске он сообщает адрес родителю.

## Что улучшено в библиотеке

Предыдущий этап исправил сравнение `deriveStore`, терявшее изменения `0 → false` и `0 → "0"`.
Освобождение линий выявило ещё два дефекта Listen: ошибочное добавление оставляло callback и
обработчик закрытия, а ошибка удаления могла оставлять callback в быстром диспетчере.
Исправления проверяют также повторное создание подписки с тем же ключом внутри обработчика.
Публичные сигнатуры библиотеки сохранены.

Исходники: `experiments/wenay-scaffold/examples/smart-home`; копии `.ts` обновляются через
`npm run examples:generate`. Проверка устанавливаемого пакета: `npm run test:example:smart-home`
из корня репозитория после сборки.
